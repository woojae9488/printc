# 그림

이미지 파일로 색별 그림 gcode를 만드는 방법.

- 도구: `@tools/cream_image.py`. 전체 인자는 `-h`.
- 설치는 `@docs/lettering.md`. 케이크, 크림 선, 테두리, 꽃 등 공통 인자는 글씨와 같고 `-h`에 있음.
- 의존: `@tools/requirements.txt`. 기존 설치 후 `pip install -r`을 다시 수행.

## 사용법

```
.venv/bin/python tools/cream_image.py image.png --out out/job.gcode --preview out/job.svg
```

- 이미지: PNG, JPEG, BMP, GIF, WEBP. 저장소 밖 경로도 가능.
- 투명한 곳은 흰색으로 봄.
- `--colors`: 그릴 색 수. 기본 3. 배경은 세지 않음.
    - 배경은 이미지 테두리와 닿은 색. 그리려면 `--draw-background`.
    - 배경을 그리면 배경도 한 색으로 세므로 `--colors 2` 이상.
    - 비슷한 색은 합치고 아주 작은 색은 뺌. 남은 색 수가 적으면 생성 메시지에 출력.
    - 색은 Lab 거리로 나눔. 밝기가 같은 분홍과 회색도 갈림.
- `--size`: 그림 긴 변 mm. 생략 시 케이크 안 최대. 모든 색이 같은 크기, 같은 위치.
- `--style`, `--fallback`: 글씨와 같음. 폴백 사다리는 `@docs/lettering.md`.
    - 조각 단위로 적용. 폴백을 쓴 조각 수를 생성 메시지에 출력.
    - `auto`는 사다리 끝에 `line` 단계를 더함. 굵기 판정 없이 가는 부분을 중심선 한 줄로 그림.
    - 폴백으로도 못 그리는 조각(선 폭보다 작은 점)은 건너뛰고 개수를 경고로 출력.
    - `--fallback`을 직접 골라도 같음.
- 생성 메시지에 색별 파일, 실제 그림 크기, 자동, 지정 여부 출력.
- `--preview`: 색별 경로를 한 SVG에 그림.

## 일러스트화

- `--simplify`(기본 켬): 색을 나누기 전에 이미지를 일러스트처럼 단순화.
    - 중간값 필터로 질감, 잡음을 지움.
    - 색을 줄인 뒤 다수결로 잔 얼룩을 지워 경계를 매끈하게 함.
- `--no-simplify`: 원본 그대로 색만 줄임. 선화, 로고처럼 이미 단순한 이미지에 사용.
- 일러스트화와 사진 보정의 상수는 `@tools/imageregion.py`.

## 사진 보정

- `--photo`: 사진 보정. 생략 시 자동, 끄려면 `--no-photo`.
    - 자동은 조명을 편 뒤에도 이미지 테두리가 한 색으로 균일할 때만 켬. 생성 메시지에 표시.
- 보정 내용:
    - 테두리(배경)로 조명 곡면을 맞춰 나눔. 위아래 밝기 차, 그림자가 줄어듦.
    - 배경과 색이 다른 큰 덩어리의 볼록 껍질만 잘라 다시 작업 해상도로 줄임.
        - 접힌 선, 먼지, 그림자는 빠지고 대상의 해상도가 늘어 가는 선이 살아남음.
        - 대상이 이미지 대부분이면 자르지 않음.
    - 대상 가장자리와 닿은 색은 전부 배경으로 봄. 천 위의 흰 스티커 바탕도 빠짐.
    - `--draw-background`면 배경 중 가장 넓은 색(스티커 바탕) 하나만 그림.
- 테두리가 한 색이 아니거나(가장자리까지 찬 그림) 대상을 못 찾으면 보정 없이 일반 이미지로 처리.
    - 기울기 있는 배경 위의 단색 그림은 색이 여러 층으로 갈릴 수 있음. 그럴 땐 `--no-photo`.
    - 보정하면 `--draw-background`의 배경은 원본 사각형이 아니라 대상 둘레 모양.

## 출력 방식

- `--files split`(기본): 색마다 gcode 하나. `job_1.gcode`, `job_2.gcode`, …
    - 모두 `T0`만 씀. 순서는 면적이 큰 색부터.
    - 색은 생성 메시지와 gcode 머리 주석에 표시. 색이 하나면 `--out` 이름 그대로.
    - 이전 실행의 같은 이름 파일이 남으면 경고. 오래된 파일은 지우고 실행.
- `--files single`: gcode 하나에 `T0`, `T1`, …로 색을 전환.
    - 카트리지별 색은 생성 메시지와 gcode 머리 주석(`T0 #rrggbb / T1 …`)에 표시.
    - 색 수가 `@hardware/active/cream_vars.cfg` `variable_tool_count`를 넘으면 오류. `split` 사용.
- `--colors 2` 이상이면 `--border`, `--flowers` 사용 불가. `T1`, `T2`를 이미 씀.
    - 쓰려면 `--colors 1`.
- 모든 파일은 한꺼번에 씀. 쓰다 실패하면 기존 파일은 그대로이고 새 파일은 만들어지지 않음.

## 실행 절차

- 모든 파일(`split`)과 색 전환(`single`)은 `T<n>`에서 교체 위치로 가서 `PAUSE`.
    - 그때 카트리지를 교체하고 `RESUME`. 매크로는 `@klipper/macros/cream.cfg`.
    - 미리 끼우면 밀대가 표시선 아래인 채로 빼게 되므로 `PAUSE` 전에 끼우지 않음.
- `split`은 파일 사이에 케이크를 판에서 옮기지 않음. 옮기면 색이 어긋남.
    - 색마다 위치와 크기가 같아야 하므로 `--out` 외 인자를 바꿔 다시 생성했다면 색 전체를 다시 짬.
- 파일 사이 대기가 길면 모터가 꺼져 밀대 위치를 잃음.
    - 대응은 `@docs/troubleshooting.md` "쉬는 동안 밀대가 올라감".
- 파일이 끝난 직후 깍지 끝에 크림이 맺혀 있을 수 있음. 교체 전에 케이크 위로 떨어지지 않는지 확인.

## 이미지 고르기

- 일러스트, 만화풍, 로고, 실루엣처럼 색 영역이 뚜렷한 이미지가 적합.
- 사진은 `--photo`로 어느 정도 쓸 수 있으나 원본 로고, 스캔이 더 좋음.
    - 너무 복잡하면(`MAX_RUNS`) 오류. 색이 번져도 그릴 윤곽이 없다는 오류.
    - 사진 속 대상이 작으면 대상만 잘라서 사용. 해상도가 높을수록 가는 선이 살아남음.
- 선 폭보다 가는 부분은 중심선 한 줄로 그려 실제보다 굵게 나옴.
    - 글씨는 `@tools/cream_text.py`로 따로 생성.
- 미리 보기(SVG) 읽는 법:
    - 케이크 바탕은 크림색, 획 밑은 어두운 테두리라 밝은 색도 보임.
    - 주황 점선은 폴백으로 그린 획. 회색 점선은 이동.

## 한계

- 윤곽을 채워 그림. 선 두께 변화, 명암은 표현 못 함.
- 비슷한 색은 한 색이 됨.
    - 경계의 흐린 띠는 `MIN_LAYER_WIDTH_PX`보다 가늘면 버림. 아주 흐린 경계는 색으로 남을 수 있음.
- 이미지는 긴 변을 `WORK_MAX_PX`로 맞춰 처리. 잔 무늬는 사라짐.
- 짜는 순서는 조각의 읽는 순서(위에서 아래, 왼쪽에서 오른쪽). 이동 최적화 없음.
- 색 경계는 서로 닿게 짬. 겹치거나 틈을 두지 않음. 실제 크림으로 확인 필요.
- 글씨와 한 번에 못 그림. 별도 gcode로 생성.
